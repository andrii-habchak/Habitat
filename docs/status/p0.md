## Defaults taken

1. Convention doc is a new file `docs/accessibility-ids.md` (the task says "documented in
   docs/"; it is not one of the orchestrator's files).
2. `LaunchOptions` lives in `HabitatCore` so `swift test` covers it without a simulator.
   `today` is a validated `yyyy-MM-dd` string; P1 should switch it to its `DayKey` type.
3. Malformed values are dropped, not guessed: `-today 2026-02-30` → no override; a flag whose
   next argument starts with `-` takes no value and does not swallow that flag. The last
   valid occurrence wins: a later malformed `-today` leaves an earlier valid one in place.
   Unknown arguments are ignored.
4. Tab buttons are found by label in UI tests (SwiftUI's `.tabItem` does not reliably forward
   identifiers); `tabs.<tab>` is still set on the label.
5. Tab icons: `checklist`, `calendar.day.timeline.left`, `calendar`, `bell`, `gearshape`.
6. iPhone only (`TARGETED_DEVICE_FAMILY = 1`, set on both targets because xcodegen
   defaults targets to `1,2`), portrait only. Marketing version `0.1.0`.
7. `DEVELOPMENT_TEAM` empty in `project.yml`; the owner picks the personal team in Xcode for
   device builds. Simulator builds need no team.
8. The fast gate uses `build-for-testing` with `generic/platform=iOS Simulator`, so the UI test
   target compiles without a simulator. `full` reuses the same DerivedData and runs
   `xcodebuild test -destination id=<udid>`, UDID from `<main checkout>/.run/sim-udid`
   (found through `git rev-parse --git-common-dir`, so it works from worktrees) or
   `HABITAT_SIM_UDID`. Result bundles go to `build.noindex/results/`.
9. Gate logs go to `build.noindex/logs/<step>.log`; on failure the errors and log tail are
   printed. SwiftLint cache, SwiftPM scratch, DerivedData and package caches are all under
   `build.noindex/`.

## Fix: Month placeholder contrast (branch `ph/p0-fix-month`)

QA finding (`docs/status/p0-qa.md`): `performAccessibilityAudit()` failed on the Month tab with
"Contrast failed" on the "Month" static text; the other four tabs passed.

- Diagnosis (from the code, not confirmed in a simulator): all five placeholders share
  `FeaturePlaceholder`; only the title and SF Symbol differ. `ContentUnavailableView` puts the
  `Label(title, systemImage:)` in one text element whose frame covers the large
  secondary-colour icon as well as the title, so the audit samples the icon's grey pixels as
  text colour. `calendar` (Month) has a solid header band and much more grey area than the
  thin-stroke `checklist`, `bell`, `gearshape` and `calendar.day.timeline.left`, which tips it
  under the contrast threshold.
- Fix: `FeaturePlaceholder` draws its own layout: a decorative icon, hidden from
  accessibility and outside the text element, then a title (primary) and the "Not built yet."
  line (secondary) combined into the `<tab>.placeholder` element. The look stays close to
  `ContentUnavailableView`.
- `TabShellTests.testAuditMonth` no longer wraps the audit in `XCTExpectFailure`; QA to
  re-verify with `scripts/gate.sh full`.
