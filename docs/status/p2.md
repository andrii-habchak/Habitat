## Defaults taken

1. Repositories are `@MainActor` and use the container's `mainContext`; `Habit`/`Completion`/
   `Reminder` values cross the API, not model objects.
2. A habit is created today; name is trimmed; new habits go after the current last `sortOrder`.
3. `archive` without a day uses today; archiving an archived habit keeps the first archive day.
   `unarchive` keeps the old list position.
4. `reorder(ids)`: listed habits first in that order, the rest (archived) follow in their old
   order; sort orders are renumbered 0...n-1; an unknown id throws and changes nothing.
5. `toggle` is refused for a future day (`futureDay`), an unknown habit, and a day the habit does
   not count (before created or after archived: `habitNotActive`).
6. `completions(from:through:)` includes archived habits' completions up to their archive day;
   callers filter habits they do not show. Export is unfiltered (lossless).
7. Reminder for a missing habit is refused (`habitNotFound`).
8. Import merge: records whose id already exists are kept as they are (the store wins, the file's
   copy is ignored); new habits are appended after existing ones keeping their relative order
   (sort orders renumbered); completions are a union; new reminders are validated in file order
   against the store plus the already accepted ones, and the first clash aborts the whole import
   with `ImportError.invalidReminder(index:reason:)`.
9. Import replace: store becomes the file; records with a shared id are updated in place.
   Sort orders are kept as in the file.
10. Seeding happens only when the store holds no habits and no reminders; unknown fixture name
    throws `SeedError.unknownFixture`.
11. Fixtures: `typical` = Read, Workout (3/wk), Meditate, Water, Call family (1/wk), created 28 days
    before today, done when `(habit index + days back) % 3 != 0` over the last 7 days, reminders
    "Plan the day" (Mon-Fri 08:00) and Read (daily 21:00). `streaks` = daily 10, daily 3 (today
    open), weekly 3/wk 4 (four full previous weeks Mon/Wed/Fri, current week empty).
12. Notification content: general reminder title = label, body "Reminder"; habit reminder title =
    habit name, body "Time for <name>". Requests fire once at a calendar date/time (no repeats);
    category `habitat.habitReminder` with a "Mark done" action registered by
    `UserNotificationScheduler.registerCategories()` (to be called by P6).
13. Fake scheduler status starts `authorized` unless set; `requestAuthorization` moves it to
    granted/denied.
