# P6 — Reminders: status

Branch `ph/p6-reminders`. State: implemented, `scripts/gate.sh fast` green. Ready for review and QA.

## Done

All in `App/Habitat/Features/Reminders/`, plus the minimal hook-up in `App/Habitat/HabitatApp.swift`:

- `RemindersView.swift`: the screen. List grouped as "General" and one section per habit (habit
  order as stored; a missing habit shows "Deleted habit", an archived one "<name> (archived)").
  Each row: label or habit name, local short time, weekday summary; tap opens the editor; swipe to
  delete. Empty state, permission section, inline errors. `ErrorText` (shared by the editor) uses
  `Theme.Status.failed` plus an icon.
- `ReminderEditorView.swift` / `ReminderEditorModel.swift`: sheet with kind (segmented General |
  Habit), label field or habit picker (active habits), time (`DatePicker` hour/minute), weekday
  chips Mon-Sun, Save/Cancel, Delete when editing. Saving goes through `ReminderRepository`, so the
  HabitatCore duplicate rule applies; the `ReminderError` text (naming the clashing reminder) is
  shown inline at the top of the form and announced to VoiceOver.
- `RemindersViewModel.swift`: list state, grouping, row text and VoiceOver label
  ("Reminder: Water, 8:00 AM, Monday, Wednesday" / "Habit reminder: Read, 9:00 PM, Every day"),
  `ReminderFormat` (time and day text), `ReminderTimeConversion` (`Date` <-> `ReminderTime`).
- `ReminderSync.swift`: `@MainActor @Observable` re-planner and permission state.
  `replan()` reads reminders, habits and completions (today through the 14-day window) and calls
  `NotificationSync.replaceAllPending` with `clock.now()`. Calls while a pass runs fold into one
  more pass. A failed pass is retried once (the system scheduler can leave a partial set pending;
  every pass removes all first). The last failure is shown on the screen (`reminders.syncError`).
  Scheduler: `FakeNotificationScheduler` with `-fakeNotifications`, `UserNotificationScheduler`
  otherwise.
- `ReminderNotificationDelegate.swift`: `UNUserNotificationCenterDelegate` installed at launch
  (`HabitatApp.init`). With the system scheduler it registers the "Mark done" category
  (`UserNotificationScheduler.registerCategories()`). A "Mark done" response parses the request
  identifier `<reminder uuid>.<yyyy-MM-dd>` for the day and `userInfo["habitID"]` for the habit
  (`MarkDoneTarget`), marks the habit done via `CompletionRepository` (only if not done yet) and
  re-plans before returning. Foreground notifications are shown as banner + list + sound.
- `HabitatApp.swift`: creates `ReminderSync` and the delegate, injects
  `.environment(\.reminderSync, ...)`, and re-plans plus refreshes the permission state on every
  `scenePhase == .active` (`initial: true`, so also at launch).

### Hook for other lanes (habit toggles)

```swift
@Environment(\.reminderSync) private var reminderSync
// after a toggle, create, archive, unarchive or rename:
reminderSync?.replan()
```

`nil` only in previews. Not wired into Habits/Week/Month here (their folders are not mine); the
orchestrator or those lanes add the one line after each `CompletionRepository.toggle` and habit
change. Until then the plan is refreshed on launch, on foreground and on every reminder change.

## Defaults taken

1. New reminder: kind General, time 09:00, all seven weekdays selected, first active habit
   preselected for the Habit kind.
2. Sections: "General" first, then one per habit in stored habit order; rows by time (repository
   order). Reminders of an archived habit stay listed as "<name> (archived)"; their habit stays
   selectable when editing.
3. Weekday summary: "Every day", "Weekdays" (Mon-Fri), "Weekends" (Sat-Sun), otherwise
   "Mon, Wed"; VoiceOver reads full day names.
4. Time is shown in the device's short time style (12/24-hour as set); stored as hour/minute.
5. Permission is asked after the first successful save while it is not determined, or with the
   "Allow notifications" button; creating reminders never waits for it. Denied shows the banner
   with "Open Settings" (`UIApplication.openNotificationSettingsURLString`).
6. Scheduling runs whatever the permission state (harmless when denied; picked up as soon as the
   user allows it and returns to the app).
7. "Mark done" marks the day named in the request identifier (the reminder's day), never
   un-marks, and ignores the response if the identifier or habit id cannot be parsed or the
   repository refuses (future day, inactive habit). The refusal is not shown: the re-plan that
   follows clears `lastErrorMessage` when it succeeds.
8. Notifications arriving while the app is open are shown (banner, list, sound).
9. Duplicate rule as in HabitatCore: general reminders clash regardless of label
   (STATUS "Decisions for owner" #5, kept).
10. Editor error sits at the top of the form (the Save button is in the toolbar) and is also
    posted as a VoiceOver announcement.

## Not done / notes

- No unit tests for the view models: the app has no unit-test target and adding one needs a
  `project.yml` change (not mine). The pure parts worth testing (`MarkDoneTarget` parsing,
  `RemindersViewModel.sections`, `ReminderFormat`) are static and would move easily.
- A "Mark done" while the app is open updates the store, but other screens refresh only when they
  reload (they are not observed from here).
- `-fakeNotifications` always reports "authorized", so UI tests cannot show the denied banner;
  a launch argument for a denied fake would need a `LaunchOptions` change (HabitatKit, not mine).
- Shell UI tests that look for `reminders.placeholder` need updating by QA (`reminders.screen`).
- Not run in a simulator (QA does).

## Re-plan hooks wired

`reminderSync?.replan()` now runs after each successful change to completions or habits:

- Week: `WeekPage` (`Features/Week/WeekView.swift`), after `WeekViewModel.toggle` stores the toggle.
- Month and day sheet: `MonthView.toggle` (`Features/Month/MonthView.swift`, the `DaySheet` `onToggle`), after the toggle is stored.
- Habits create/edit: `HabitEditorView` Save (`Features/Habits/HabitEditorView.swift`), after `save()` succeeds.
- Habits archive, unarchive, reorder: `HabitsView` (`Features/Habits/HabitsView.swift`), after the
  `HabitsViewModel` call reports it was stored.

The view models' `toggle`, `archive`, `unarchive` and `move` return whether the change was stored
(`@discardableResult`); a failed change does not re-plan.
